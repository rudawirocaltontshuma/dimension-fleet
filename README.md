# DIMENSION FLEET

**Fleet & Logistics Management Platform** — a frontend-only, portfolio-grade demo of an enterprise transportation-management interface.

<img src="https://github.com/arhamkhnz/next-shadcn-admin-dashboard/blob/main/media/dashboard.png?version=5" alt="Dashboard Screenshot">

Dimension Fleet simulates a full fleet & logistics operations console — dashboards, vehicles, drivers, trips, routes, deliveries, dispatch, maintenance, fuel, incidents, inspections, locations, documents, reports, and analytics — all running on deterministic, seeded, fictional mock data. There is no backend, database, authentication, real API, GPS/telematics integration, or persistence: every interaction (status changes, dispatch moves, settings) is in-memory only and resets on reload.

> Live under `/dimension-fleet/...` (e.g. `/dimension-fleet/dashboard`, `/dimension-fleet/vehicles`). The root route `/` redirects to `/dimension-fleet/dashboard`.

## Modules

| Module | Route | Highlights |
| --- | --- | --- |
| Dashboard | `/dimension-fleet/dashboard` | 8 fleet KPIs, 6 Recharts visualizations, recent incidents, upcoming maintenance |
| Fleet | `/dimension-fleet/fleet` | Fleet-wide overview |
| Vehicles | `/dimension-fleet/vehicles`, `/dimension-fleet/vehicles/[id]` | Directory + detail page with Overview, Trips, Maintenance, Fuel, Inspections, Incidents, Documents, Timeline tabs |
| Drivers | `/dimension-fleet/drivers`, `/dimension-fleet/drivers/[id]` | Directory + detail page with Profile, Trips, Performance, Safety, Incidents, Activity tabs |
| Trips | `/dimension-fleet/trips` | Scheduled → Dispatched → In Transit → Completed / Cancelled |
| Routes | `/dimension-fleet/routes` | Stylized abstract SVG route visualizations (no real map library) |
| Deliveries | `/dimension-fleet/deliveries` | Status updates with toast confirmation |
| Dispatch | `/dimension-fleet/dispatch` | 5-column Kanban board with native HTML5 drag-and-drop (in-memory only) |
| Maintenance | `/dimension-fleet/maintenance` | KPIs + service records table |
| Fuel | `/dimension-fleet/fuel` | Fuel consumption, cost, and efficiency trend charts |
| Incidents | `/dimension-fleet/incidents` | Severity-ranked incident log |
| Inspections | `/dimension-fleet/inspections` | Inspection results and status |
| Locations | `/dimension-fleet/locations` | Depots and distribution/service centers |
| Documents | `/dimension-fleet/documents` | Document center grouped by category |
| Reports | `/dimension-fleet/reports` | Report hub with mock export |
| Analytics | `/dimension-fleet/analytics` | 6 tabbed analytics sections built on Recharts |
| Settings | `/dimension-fleet/settings` | Mock preferences (toast-only, no persistence) |

## Mock data

All data is generated by a seeded, deterministic generator in `src/lib/dimension-fleet/` — nothing is fetched from a network or stored server-side:

- 100+ vehicles, 80+ drivers, 200+ trips, 300+ deliveries
- 150+ maintenance records, 300+ fuel records, 80+ incidents, 200+ inspections
- A handful of depots/distribution centers and derived documents

## Tech Stack

- **Framework**: Next.js (App Router), TypeScript, Tailwind CSS
- **UI Components**: shadcn/ui
- **Icons**: lucide-react
- **Charts**: Recharts
- **Tooling & DX**: Biome, Husky

## Getting Started

### Run locally

1. **Clone the repository**
   ```bash
   git clone https://github.com/rudawirocaltontshuma/fleet_logistics_management.git
   ```

2. **Navigate into the project**
   ```bash
   cd fleet_logistics_management
   ```

3. **Install dependencies**
   ```bash
   npm install
   ```

4. **Start the development server**
   ```bash
   npm run dev
   ```

Your app will be running at [http://localhost:3000](http://localhost:3000) — visit `/dimension-fleet/dashboard` (or just `/`, which redirects there).

### Build

```bash
npm run build
```

### Formatting and Linting

Format, lint, and organize imports
```bash
npx @biomejs/biome check --write
```
> For more information on available rules, fixes, and CLI options, refer to the [Biome documentation](https://biomejs.dev/).

## Project structure

Dimension Fleet is colocated under its own namespace inside a larger Next.js admin-template workspace:

```
src
├── app
│   └── dimension-fleet        # All Dimension Fleet routes (dashboard, vehicles, drivers, ...)
├── components
│   └── dimension-fleet        # DataTable, KpiCard, StatusBadge, ChartCard, RouteMap, app shell
└── lib
    └── dimension-fleet        # Mock data generators, aggregation, and formatting helpers
```

## Scope & disclaimers

This is a **frontend-only demonstration project** built for a portfolio. It intentionally does not include:

- A backend, database, or persistence layer
- Authentication or authorization
- Real APIs or external integrations
- GPS, telematics, or real-time vehicle tracking
- Real-world dispatching
